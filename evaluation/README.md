# Evaluation Framework

## What this folder contains

| File / folder        | Purpose                                                        |
| -------------------- | -------------------------------------------------------------- |
| `questions.json`     | Template for your FINAL 30+ question-answer pairs (example entries removed by the scripts). |
| `questions_sample.json` | 30+ REAL questions grounded in the sample PDFs (generated by `scripts/create_sample_pdfs.py`). |
| `results/`           | Generated outputs: `answer_quality.csv`, `retrieval_failures.json`. |
| `FAILURE_ANALYSIS.md`    | Template to record real failures after evaluation.            |

## Writing your real evaluation set (30+ questions)

1. Finalize your 10–20 PDFs in `data/documents/` and run `python scripts/ingest.py`.
2. Replace the example entries in `questions.json` with real questions. For every
   question provide:
   - `id` – unique integer
   - `question` – the question text
   - `expected_answer` – a short reference answer
   - `expected_sources` – `[{"document": "<file name>", "page": <real page>}]`

The `expected_sources` document names and page numbers **must** match real pages
in your PDFs, otherwise retrieval will be scored as a miss.

### Best practice for source pages

Open the PDF, find the exact page where the answer appears, and record it.
Keep at least one or two questions with **empty** `expected_sources` to test the
"I don't know" path (out-of-scope questions).

## Running evaluation

```bash
python scripts/evaluate.py                    # retrieval metrics + answers (needs key)
python scripts/evaluate.py --questions evaluation/questions_sample.json
python scripts/evaluate.py --top-k 5
```

### What is automated vs manual

- **Automated:** retrieval Hit Rate @ 3 / @ 5 / @ 8 and MRR, plus citation
  veracity (do the `[n]` numbers the model used exist in the retrieved context?).
- **Manual:** answer correctness and groundedness. The rubric is 1–5:

  | Score | Meaning |
  |------:|:--------|
  | 1 | Incorrect |
  | 2 | Mostly incorrect |
  | 3 | Partially correct |
  | 4 | Mostly correct |
  | 5 | Fully correct |

Review `results/answer_quality.csv` and fill in `correctness_score` and
`groundedness_score` (both 1–5). Unfilled cells are left blank on purpose —
no automated script pretends to be a human evaluator.

## Reading retrieval_failures.json

Any question whose expected source was not retrieved is written to
`results/retrieval_failures.json` with the expected document/page and the top
results that were actually returned. Feed these into `FAILURE_ANALYSIS.md` to
distinguish real retrieval failures from bad evaluation questions.
